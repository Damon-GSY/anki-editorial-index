# Task brief

## Authority and scope

- Controller / user instruction: “必须要参考 [catppuccin/catppuccin]里面的配色，每个不同的 theme 里面都有不同的颜色组合，你都去调整下。”
- Deliverable surface: the existing Editorial Index Anki add-on, its WebView and Qt-native surfaces, automated fixtures, package, and public README gallery.
- State count: Deck Browser, reviewer, editor/dialog, selection/focus, and Review Heatmap states across Latte, Frappé, Macchiato, and Mocha.
- Editable-source requirement: Python, CSS, JSON, HTML fixture, and tests remain the source of truth; screenshots are generated evidence.
- Interaction policy: user-directed revision of an already selected Editorial Index interface direction.

## Image role preflight

- Image role status: approved
- Image role: reference
- Image placement: not-placed
- Image role approval evidence: the user supplied the Catppuccin repository as the required reference.
- Image role source/rights: Catppuccin repository and style guide, MIT licensed; referenced as design evidence and not bundled as imagery.

## Reader and truth

- Reader action and viewing condition: study and manage Anki cards for long desktop sessions while immediately recognizing navigation, state, status, focus, and recovery actions.
- Required facts: four official Catppuccin flavors; 26 official tokens per flavor; all 14 selectable accents; exact upstream raw values; readable interactive text.
- Required behavior: preserve collections, scheduling, card templates, shortcuts, open editor content, live theme switching, and the warm-paper Editorial default.
- Refusals: a monochrome accent wash; one selected accent reused for every semantic role; invented Catppuccin colors; inaccessible raw accent text; copied Catppuccin website layout.
- Allowed sources: current repository, the official Catppuccin repository, its style guide, its palette package, and project-owned test fixtures.
- Unknowns: Catppuccin does not prescribe an Anki-specific New/Learn/Due mapping, so those roles must follow the nearest official information/warning/error/success semantics and Anki conventions.

## Asset decision

- Content-essential assets: generated screenshots proving each flavor and semantic role; removal would make the theme differences harder to verify.
- Identity assets: none.
- Supporting-atmosphere assets: none.
- Source / rights / generation route: screenshots generated locally from the add-on's own CSS and official palette snapshot.

## Form questions

- Role of each state: Deck Browser proves hierarchy and learning statuses; reviewer proves decision semantics; editor/dialog proves fields, focus, selection, and recovery; palette sheet proves all official raw tokens.
- Viewer distance, dwell time, and access context: desktop, arm's length, repeated daily use, potentially long sessions.
- Capacity check: existing Anki labels, long translated labels, 320–1440 px fixture widths, and 2/3/4 rating modes remain covered.
- Current-task visual mother object: a calm indexed workspace whose UI layers expose the full Catppuccin semantic ladder.
- Title-removal test: Base/Mantle/Crust, Surface, Overlay, typography, status, link, focus, cursor, and accent roles remain recognizably Catppuccin.
- Single-canvas counterfactual: fails; this is a product state system and requires multiple states and all four flavors.

## Form challenge

1. Authority: the user's instruction fixes the existing Anki add-on as the carrier and the official Catppuccin repository as the reference.
2. Reader action: users compare four flavors and then operate Anki states; a multi-state UI and generated comparison captures fit that task.
3. Single-canvas test: one image cannot prove native dialogs, fields, focus, reviewer ratings, and all flavor mappings; retain the state system.

## Autonomous fallback

- Least-assumptive permitted choice: preserve layout, typography, configuration, and accent selection; change only Catppuccin semantic color ownership.
- Counterfactual result and unresolved risk: copying a fixed showcase accent per flavor would invent an upstream recommendation, so the user-selected accent remains configurable while functional roles use official named tokens.
